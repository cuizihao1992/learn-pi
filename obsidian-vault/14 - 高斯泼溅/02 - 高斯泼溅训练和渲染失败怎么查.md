# 高斯泼溅训练和渲染失败怎么查

高斯泼溅的问题通常不在一个地方：可能是照片质量、相机位姿、初始化点云、训练参数、显存、排序混合、viewer shader。调试时要沿完整链路排查。

## 常见问题表

| 现象 | 可能原因 | 检查点 |
| --- | --- | --- |
| 训练一开始就很糊 | 相机位姿差、照片模糊、COLMAP 稀疏点太少 | 先看 sparse reconstruction 和相机覆盖。 |
| 场景漂浮或错位 | 相机外参错误、坐标系转换错误 | 检查 COLMAP 输出、坐标轴方向、viewer 相机。 |
| 显存爆掉 | 高斯数量过多、分辨率过高、densify 太激进 | 降低分辨率，调 densification interval/threshold。 |
| 噪点很多 | 透明度/协方差异常，高斯贡献太碎 | 检查 pruning、opacity reset、学习率。 |
| 边缘闪烁 | 排序不稳定、半透明混合误差、过大 splat | 看 depth sort、tile binning、scale 分布。 |
| 近处过曝 | alpha 累积或颜色优化异常 | 检查 opacity、SH degree、曝光/白平衡一致性。 |

## 检查顺序

- 照片： 是否模糊、曝光差异大、动态物体多、重叠视角不足。

- COLMAP： 相机数量、稀疏点云质量、重投影误差、坐标尺度是否合理。

- 初始化： Gaussian 数量是否过少或过多，初始尺度是否异常。

- 训练： loss 是否下降，densify/prune 是否让点数爆炸。

- 渲染： 屏幕投影是否正常，tile 覆盖是否过大，alpha 是否快速饱和。

- viewer： shader、排序、相机矩阵、坐标系是否和训练一致。

## 关键指标

- Gaussian count： 太少表达不了细节，太多会爆显存和拖慢渲染。

- opacity 分布： 大量接近 0 的点说明需要 prune；大量接近 1 可能导致透明混合饱和。

- scale 分布： 过大的高斯会糊，过小的高斯会噪。

- loss 曲线： 不下降先查数据和相机，不要先调 shader。

## 最重要的一句话

高斯泼溅的质量首先由数据和相机位姿决定，其次才是训练参数和 rasterizer。相机错了，后面所有优化都只是在错误几何上变漂亮。
