# 量化需要什么服务器资源

资源要求取决于周期。日频研究可以用普通电脑；分钟级实盘需要稳定服务器；高频交易需要低延迟网络、交易所附近机房和专业风控。入门者不要一开始追求高频。

| 阶段 | 资源建议 | 说明 |
| --- | --- | --- |
| 学习/日频回测 | 本机 4-8 核 CPU、16GB 内存、SSD | 足够做 pandas 回测、因子分析、小数据集。 |
| 中等规模研究 | 8-16 核、32-64GB 内存、1TB SSD | 适合多年分钟线、多因子矩阵、并行参数测试。 |
| 日频/分钟实盘 | 云服务器 2-8 核、8-32GB 内存、稳定网络 | 重点是稳定、日志、告警、自动重启。 |
| 高频/低延迟 | 专线、托管机房、低延迟语言和网卡 | 不是入门方向，工程和合规成本极高。 |

## 实盘最小架构

```text
行情进程
  -> 策略进程
  -> 风控检查
  -> 下单进程
  -> 成交回报
  -> 持仓同步
  -> 日志和告警
```

最低限度也要有：日志文件、异常告警、断线重连、每日最大亏损限制、单票最大仓位、重复下单保护、手动一键停止。真正危险的不是策略亏钱，而是程序失控。

## 风控清单

- 单笔订单金额上限。

- 单票仓位上限和行业仓位上限。

- 每日最大亏损和最大下单次数。

- 行情延迟超过阈值时停止交易。

- 券商持仓和本地持仓不一致时停止交易。

- 策略异常报错时进入只撤单/只减仓模式。

## 入门技术栈

研究用 Python、pandas、numpy、polars、duckdb、jupyter。数据存储可以先用 CSV/Parquet，规模上来后用 PostgreSQL、ClickHouse 或对象存储。实盘服务可用 Python + systemd/pm2/docker，监控可以从日志、邮件、Telegram/企业微信告警开始。
