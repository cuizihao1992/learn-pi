Module Charter

LLM 与 Agent：把术语组织成一个可推导的系统

本模块以系统理解为目标。每个概念都要回答输入是什么、中间表示是什么、计算发生在哪里、输出如何验证，以及它与相邻组件如何协作。

学习目标

  • 解释 embedding、检索、重排、上下文构造和生成之间的边界。
  • 区分参数记忆、上下文、KV Cache、外部记忆和业务状态。
  • 面对长上下文、RAG、微调和工具调用时，能根据问题选择方案。
  • 用“定义、机制、例子、取舍、验证”完整回答一道系统题。

模块边界

这里训练 LLM 应用系统的通用心智模型与技术表达，不背厂商接口清单。Pi 源码进入 Pi Agent 模块，最小实现进入 Mini Agent，GPU 推理瓶颈进入推理加速模块。

核心链路

user problem
  -> task and risk definition
  -> choose context / retrieval / tools / memory
  -> construct model input
  -> inference and tool loop
  -> grounded output
  -> offline evaluation + online feedback
  -> improve data, policy or system

必须深挖的一个点

Embedding 为什么能用于检索，却不等于“模型理解了事实”？亲手比较三个句子的向量相似度，再构造一个语义相近但事实错误的反例，理解召回只是在候选空间中找近邻。

实践产物

  • 运行 Mini RAG，并记录一次召回错误如何传播到最终答案。
  • 画出一种记忆系统的写入、检索、更新和遗忘策略。
  • 完成三道两分钟口述题，每道都包含机制、取舍与评估。

完成标准

遇到一个 LLM 应用问题时，能够先建立评估标准，再拆出模型、数据、检索、工具、记忆和运行时，而不是直接用某个热门名词回答。
