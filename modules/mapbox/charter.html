Module Charter

Mapbox：打穿一块矢量瓦片如何变成屏幕像素

本模块围绕一个具体问题组织：浏览器拿到一块 vector tile 后，Mapbox GL JS 如何结合 style、source、layer、worker 和 WebGL 把它画出来。学习重点是运行链路，不是罗列地图 API。

学习目标

  • 区分 source、source layer、style layer 和实际绘制数据。
  • 解释瓦片请求、后台解析、bucket 构建和主线程渲染之间的分工。
  • 根据现象判断问题位于数据、样式、坐标、网络还是 GPU 渲染层。

模块边界

这里研究 Mapbox GL JS 的矢量地图机制和工程调试。影像级三维地球进入 Cesium 模块，通用二维 GIS 数据处理进入 OpenLayers 模块，城市级系统集成进入数字孪生城市模块。

核心链路

Style JSON
 Source definition
 camera state
  -> request visible tiles
  -> worker parses vector tile
  -> features are grouped into buckets
  -> style layers select and order buckets
  -> painter submits WebGL draw calls
  -> fragments become screen pixels

必须深挖的一个点

为什么 source 里明明有数据，地图却可能什么都不显示？用同一个最小 GeoJSON 分别制造 source id、layer type、zoom、filter 和坐标顺序错误，观察它们在链路中的不同失败位置。

实践产物

  • 画一张“样式声明到 WebGL 绘制”的调用链。
  • 完成一份最小图层调试记录，包含现象、假设、验证方法和结论。
  • 写出 Mapbox、OpenLayers、Cesium 的选择依据，而不是只比较功能数量。

完成标准

不看页面也能说清一块矢量瓦片从网络响应到像素的关键中间结构，并能用分层排查法定位“有数据但不显示”的问题。
