Roadmap

四步打穿 Mapbox 渲染链

路线围绕“一块数据为什么能显示或不能显示”展开。每一步都要留下一个可检查产物，再进入下一步。

第 1 步：建立声明模型

阅读模块总览和 Style Specification，区分 style、source、source-layer、style layer、layout 与 paint。

产物：手写一个只有 GeoJSON source 和 circle layer 的最小 Style 片段，并标出数据与外观分别在哪里定义。

第 2 步：追踪矢量瓦片

进入渲染架构，沿可见瓦片选择、网络请求、worker 解码、bucket 构建和主线程绘制追踪数据。

产物：画出 `camera -> tile -> worker -> bucket -> painter -> WebGL` 链路，并解释每层的输入输出。

第 3 步：制造故障

完成实验中的 source id、source-layer、filter、zoom 和坐标顺序错误。一次只改变一个变量。

产物：一张故障表，记录现象、所在层、验证信号和修复方法。

第 4 步：做技术选择

用相同业务需求比较 Mapbox、OpenLayers 和 Cesium，不比较“功能多少”，只比较数据规模、坐标空间、渲染目标和扩展边界。

产物：为“城市二维运营地图”和“全球三维地球”各写一份不超过 200 字的选型结论。

完成标准

  • 能解释 source 有数据但 layer 不显示的五类原因。
  • 能说清 vector tile 为什么按瓦片组织，以及 worker 为什么参与解析。
  • 能从 DevTools 网络、样式配置和相机状态逐层定位问题。
