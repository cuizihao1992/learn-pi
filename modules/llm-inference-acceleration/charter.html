推理加速内容怎么写

这个模块必须避免只堆新名词。每个加速技术都要回答四件事：原瓶颈是什么，算法怎么减少工作量，runtime 怎么把理论收益落到 GPU，限制条件在哪里。

内容标准

  1. 先区分指标：首 token 延迟、输出 tokens/s、吞吐、并发、成本、显存占用。
  2. 先讲自回归瓶颈，再讲优化技术，不要直接从 DFlash、TileRT 这些名词开始。
  3. 每个技术都要写“它省了什么”：forward 次数、显存带宽、kernel 启动、通信同步，还是 KV 读写。
  4. 必须写限制：接受率、任务类型、草稿模型成本、量化损失、硬件和 runtime 适配。
  5. 用同一个例子贯穿：生成 8 个 token，普通预测需要 8 次主模型 forward，投机解码可能只需 1 次验证。

页面模板

1. 原始瓶颈是什么
2. 一句话模型
3. 输入 -> 计算 -> 输出链路
4. 它到底省了什么
5. 为什么不会明显掉质量
6. 限制和失败场景
7. 一个数字例子
8. 来源与延伸
