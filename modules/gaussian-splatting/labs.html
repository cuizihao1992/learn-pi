把投影、conic 和 alpha 变成可观察现象

每个实验只改变一层。目标不是训练照片级场景，而是建立因果感：哪个参数改变了椭圆，哪个参数只改变颜色，tile 排序又为什么影响遮挡。

实验 1：单个屏幕 Gaussian

打开交互实验，分别移动主轴标准差、次轴标准差、旋转、不透明度和采样像素。画布中的亮度是该高斯对每个像素的最终 alpha 贡献。

打开单 Gaussian 像素实验

只改变预期现象对应源码层
σx / σy覆盖范围和二维协方差改变。`computeCov3D()` / `computeCov2D()`
rotation椭圆朝向改变，中心 weight 不变。四元数到旋转矩阵。
opacity形状不变，全部像素 alpha 同比例变化，直到 0.99 上限。`alpha = min(0.99, opacity * exp(power))`
采样像素沿长轴移动时，weight 比沿短轴衰减慢。`dᵀΣ⁻¹d`

实验 2：手算投影中心

fx = fy = 800
cx = 400, cy = 300
X = 0.2, Y = -0.1, Z = 2.0

u = fx * X/Z + cx
v = fy * Y/Z + cy

答案是 `(480, 260)`。再把 `Z` 改成 `4.0`：中心变成 `(440, 280)`，同一物体也会投影得更小，因为 Jacobian 中的 `fx/Z` 和 `fy/Z` 减半。

实验 3：证明 radius 不是椭圆本身

σx = 40 px, σy = 8 px
radius = ceil(3 * max(σx, σy)) = 120 px

这个 `120 px` 圆只负责快速找可能相交的 tile。位于短轴方向 `40 px` 的像素虽然仍在包围圆里，但已经距离短轴 `5σ`，高斯权重约为 `exp(-12.5)`，几乎没有贡献。若把 radius 当真实形状，就无法解释这一点。

实验 4：两层透明高斯为什么必须排序

设前景是红色、`α = 0.6`，后景是蓝色、`α = 0.5`，背景为黑。按前到后累积：

先红：C = 1.0 × 0.6 × red，T = 0.4
再蓝：C += 0.4 × 0.5 × blue，T = 0.2
结果 = (0.6, 0.0, 0.2)

若错误地先蓝后红：
结果 = (0.3, 0.0, 0.5)

两种结果不同，说明普通 alpha 合成不满足交换律。`duplicateWithKeys()` 把 depth 写入键中，不只是为了性能，也是为了正确的遮挡顺序。

实验 5：提前终止节省什么

连续十个高斯都给出 `α = 0.6` 时，透射率依次为 `0.4, 0.16, 0.064...`。到第十个时约为 `0.000105`，后景贡献已经很小。官方 CUDA 在下一步 `T < 0.0001` 时停止该像素的循环，减少无意义的内存读取与乘加。

自测

为什么同一高斯离相机更远时通常更小？

透视投影 Jacobian 的主项包含 `f/Z`。Z 增大时，三维协方差映射到像素空间的尺度下降。

为什么不能只存一个 radius？

radius 无法表达椭圆的长短轴和旋转方向。真正权重需要二维协方差的逆矩阵 conic。

为什么一个 Gaussian 会在排序列表中出现多次？

它可能覆盖多个 tile。实现为每个“Gaussian 与 tile 的相交”生成一个条目，使每个 tile 能独立并行处理。

训练为什么需要保存 forward 的辅助缓冲？

backward 需要知道像素处理过哪些贡献者、最终透射率以及几何和 binning 中间量，才能高效重建梯度路径。
