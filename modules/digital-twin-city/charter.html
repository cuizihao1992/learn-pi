Module Charter

数字孪生城市：让现实对象在数字系统里持续有状态

本模块不把“有一张三维地图”称为数字孪生。课程研究的是现实对象如何被标识、定位、更新、查询、可视化和驱动行动，以及这些能力如何组成一个可验证的最小系统。

学习目标

  • 区分地图底座、三维资产、业务对象、实时事件和控制动作。
  • 为一个城市对象设计静态属性、实时状态、历史序列和空间关系。
  • 解释前端、后端、消息系统、时空数据库和 Agent 的职责边界。

模块边界

课程聚焦系统架构与 MVP，不追求一次覆盖所有城市行业。单独的渲染原理回到 Mapbox、Cesium 和 OpenLayers；Agent 的模型与工具循环回到 Pi Agent。

核心链路

现实对象 / 传感器 / 业务系统
  -> identity + position + timestamp
  -> ingestion and validation
  -> current state + history + spatial relation
  -> API / event stream
  -> 2D or 3D rendering
  -> human or agent decision
  -> command, ticket or alert
  -> result returns to the state model

必须深挖的一个点

对象状态为什么不能只存在前端图层里？以一辆公交车为例，设计乱序消息、重复上报、断线重连和历史回放，理解时间戳、对象版本与幂等更新的作用。

实践产物

  • 完成一个“设备告警到处置闭环”的时序图。
  • 定义一个对象状态 JSON，并解释每个字段由谁生产、在哪里保存。
  • 给出 4 周 MVP 的范围、验收指标和明确不做的内容。

完成标准

能够从一个真实业务问题出发，画出数据进入、状态更新、地图表达、决策和反馈闭环，而不是只展示一张漂亮的三维场景。
