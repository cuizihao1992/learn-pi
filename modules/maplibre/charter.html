Module Charter

MapLibre 模块宪章

这个模块研究 MapLibre GL JS 如何把 Style、瓦片和要素变成 GPU 绘制，以及它在真实项目中为什么会空白、卡顿或选择错误。

学习目标

  • 能解释 MapLibre 与 Mapbox GL JS 的历史关系，但不把两者当前 API 和生态混为一谈。
  • 能区分 Source、Source Layer、Style Layer、layout、paint、expression 和 feature-state。
  • 能从 `Map._render()` 追踪到 `WorkerTile.parse()`、`LineBucket`、`Painter`、`Program.draw()` 与 `gl.drawElements()`。
  • 能解释为什么一条粗线最终用三角形而不是 `gl.LINES` 绘制。
  • 能在需求阶段判断应该选择 MapLibre、OpenLayers、Cesium，还是分层组合。

模块边界

这里主要研究 MapLibre GL JS 浏览器端渲染，不展开 MapLibre Native、瓦片生产平台或完整 GIS 后端。地图数据版权、服务 SLA、缓存和鉴权属于部署方案，不能因为渲染库开源就省略。

完成标准

  • 有一条从 Style 到 GPU 的真实源码调用链。
  • 有一个无需 token 的最小 GeoJSON line 示例和可观察故障实验。
  • 有 worker 与主线程分工、渲染 pass、样式表达式和拾取读路径说明。
  • 有 MapLibre、OpenLayers、Cesium 的同维度比较和决策树。
  • 关键事实链接到官方文档或固定提交源码。

源码基线

课程复核 MapLibre GL JS `6.9.0`、提交 `ae328866133a3188814b2a7b46b640b264d00ee9`。版本变化后优先复查 `src/ui/map.ts`、`src/source/worker_tile.ts`、`src/data/bucket/`、`src/render/painter.ts`、`src/webgl/draw/` 和 `src/webgl/program.ts`。
