Mini Agent 实验：把循环真正跑进脑子里

每个实验都要求保留输入、关键中间消息、输出和解释。重点不是“运行成功”，而是能指出模型、运行时和工具分别做了什么。

实验 1：手工追踪两轮 Agent Loop

任务：让 Agent 读取 `README.md` 后总结。先不要运行，手工写出消息数组在每一步的变化。

step 0: [system, user]
step 1: [system, user, assistant(toolCall: readFile)]
step 2: [system, user, assistant(toolCall), tool(toolResult)]
step 3: [system, user, assistant(toolCall), tool(toolResult), assistant(final)]

观察：最终答案之前为什么必须再次调用模型？如果省掉 `tool_call_id`，运行时会失去什么对应关系？

验收：能逐项标出哪条消息由用户、模型、工具执行器和 Agent 运行时产生。

实验 2：验证 OpenAI-compatible 最小契约

对同一个服务依次验证模型列表、普通对话和工具调用。不要只验证返回 HTTP 200，还要检查响应字段。

GET  /v1/models
POST /v1/chat/completions

request must carry:
  model, messages, tools, tool_choice

response must carry:
  choices[0].message
  choices[0].message.tool_calls[] when a tool is selected

故障注入：分别删除 `tool_calls[].id`、把 `function.arguments` 改成对象而不是 JSON 字符串、返回未知工具名。记录错误应该由 adapter 还是 Agent 层处理。

验收：能解释“模型会调用工具”和“接口格式兼容”是两件不同的事。

实验 3：攻击路径边界

检查示例中的 `resolveInsideProject()`，然后设计这些输入：正常相对路径、`../` 越界、与项目目录同前缀的兄弟目录、符号链接。仅在临时测试目录操作。

project: C:\work\demo
allowed: README.md
reject:  ..\secret.txt
reject:  C:\work\demo-backup\secret.txt
inspect: link-inside-project -> target-outside-project

观察：字符串 `startsWith(cwd)` 为什么可能把同前缀兄弟目录误判为安全？真实系统还需要规范化路径、路径分隔符边界和符号链接检查。

验收：列出至少三层保护：路径约束、工具权限、执行前确认或沙箱。

实验 4：让失败也进入上下文

让 `readFile` 读取不存在的文件，观察异常如何被转换成 `role: "tool"` 的结果。再让模型根据错误改用正确路径。

比较：直接让进程崩溃、把错误回填模型、由运行时自动重试，三种做法分别适合什么错误？

验收：能设计最大步数、超时、重试次数和不可重试错误，避免 Agent 无限循环。

自测

1. 为什么 Agent Loop 不能只写成一次模型调用？

因为模型只能请求工具，运行时执行后还要把结果回填，再让模型根据真实结果继续决策或形成最终回答。

2. 谁应该负责验证工具参数？

模型可以生成参数，但运行时必须根据 schema 和权限策略再次验证，不能把自然语言模型当作安全边界。

3. 接口返回 JSON 是否意味着模型内部也在处理 JSON？

不是。JSON 是服务协议；模型内部处理 token 和张量，服务层负责模板化输入并把生成结果解析、封装为协议对象。
